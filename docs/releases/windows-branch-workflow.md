# Windows 分支与合入工作流

## 固定分支职责

远程仓库：`https://github.com/wenchenyang874-a11y/tts_2_datasets`。

| 分支 | 职责 |
| --- | --- |
| `main` | 现有主分支，验收前维持 Web 版本；Windows 验收完成后正常合入 |
| `backup/web-2026-10-12` | 原始 Web 备份，固定在 `fcbcbb22f84797dfe9b17b81da0c9eea444fe38d`；不追加开发提交、不覆盖、不删除 |
| `feature/windows-native` | Windows 原生版本开发、规则与文档；从相同 Web 基线开始 |

本轮用户授权备份、创建开发分支和初始化文档。用户同时授权后续 Windows 版本验证通过后合入 main；本轮没有授权跳过验收。名称从用户最初所述 master 修正为仓库实际使用的 main，已由用户确认。

## 后续合入步骤

1. 在开发分支完成实现、相关文档和 [验收证据](../testing/windows-validation.md)，确认 Web 备份仍指向原始提交。
2. 获取并核对 origin/main 最新提交及已有改动，审查最终 diff；主分支有新增修改时正常整合并重新验证受影响范围，不丢弃他人修改。
3. 满足验收门槛后通过正常合并或仓库既有 PR 流程将开发分支合入 main。保留 Git 历史，不使用强制推送、硬重置主分支或删除 Web 备份来“覆盖”。
4. 核对远程、目标分支与最终提交，再推送合入结果并记录实际状态。远程保护规则要求 PR 时遵守该规则，不绕过保护。

合入内容可以替换 Web 入口，但不得在未确认数据迁移与兼容性前直接删除旧数据相关代码。回退可从 Web 备份建立修复分支或采用正常 revert；如涉及数据库变化，还必须有经过验证的数据恢复方案。

## 发布边界

本轮仅提交并推送开发文档和两条分支，不改动 main。后续本地构建、打包或合入不等于公开发布；版本号、Tag、Release 需单独授权。桌面框架和打包方式尚未确定，因此没有 Windows 构建/发布命令或已验证安装包。
