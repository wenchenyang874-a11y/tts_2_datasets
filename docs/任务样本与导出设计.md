# 任务、样本与导出设计

## 设计目标

本项目围绕四个一致性目标设计：

1. 一次点击对应一个可追踪的总任务，每条文本对应一个子任务；
2. 并发由服务端实际调度，页面数值不再只是控制 HTTP 提交速度；
3. 样本按目标唤醒词、正负语义和来源任务隔离；
4. 云费用只显示可审计的估算值，不冒充供应商最终账单。

## 任务模型

批量生成任务分为三层概念：

```text
总任务（一次点击）
└── 子任务（每条文本）
    └── 合成调用（音色 × 数量）
```

总任务汇总子任务的状态、进度、预估费用和耗时。服务端同时执行的子任务数取以下限制的最小值：

- 页面请求的批次并发；
- 服务器全局工作线程上限；
- 供应商能力或账号额度形成的实际限制。

任务时间区分：

- 排队耗时：`created_at -> started_at`；
- 执行耗时：`started_at -> finished_at`；
- 总耗时：`created_at -> finished_at`。

进程重启导致的中断任务只能标记为失败或中断，不能伪造精确完成时间。

噪声增强采用同样的任务层级：

```text
增强总任务（一次点击）
└── 子任务（每条源音频）
    └── 混音处理（该原音需要生成的增强份数）
```

每条增强样本的 `origin_job_id` 指向增强总任务，`origin_task_id` 指向对应源音频子任务。任务中心可以展开查看每条源音频的完成、失败、重复和耗时，不再把整个批次压成一条无明细任务。

## 样本语义

样本不再用一个“类型”字段混合表达多个维度：

- `target_kind`：`positive | negative | background`；
- `source_kind`：`tts | human | noise`；
- `variant_kind`：`clean | augmented`；
- `keyword_id`：该样本用于评估的目标唤醒词；
- `origin_job_id`：创建该样本的总任务；
- `origin_task_id`：直接创建该样本的子任务。

网页中的“类型”只表达是否经过噪声增强：

- 原音：`variant_kind=clean`，即所有尚未噪声增强的 TTS、真人录音和已入库背景音频；
- 增强样本：`variant_kind=augmented`。

真人录音属于“来源”而不是“类型”，使用 `provider=real` 或 `source_kind=human` 表达。增强输出不得继承源音频的审核结论：新样本固定为 `quality_status=pending`（未审核），同时只在元数据中保留 `source_quality_status` 供追溯。

负样本仍然属于某个目标唤醒词的数据集，但训练目标为 0。背景噪声素材和背景负样本不是同一个概念：噪声库文件用于增强，只有显式加入样本库后才作为可导出的背景负样本。

通用 JSONL 除 `target_kind`、二值 `target`、来源、增强状态、唤醒词和父子任务来源外，还记录音色、模型、语速、音高、供应商音量级、供应商请求参数、归一化音频参数、时长、质量状态和完整扩展元数据。

WeKWS Max-Pooling 兼容导出把关键词映射为一个 ASCII token（默认 `<NI_HAO_XIAO_ZHU_SHOU>`，类别 `0`），负样本和背景样本统一使用标准 `<FILLER>`（类别 `-1`），不会把中文标签逐字拆成多个类别。压缩包同时包含：

- `wekws/dict/dict.txt` 与 `words.txt`；
- 每个数据划分的 `text`、`wav.scp`、`wav.dur`；
- 可直接传给上游 `tools/make_list.py` 的说明。

## 音频参数

生成页面中的厂商参数表示“向供应商请求的音频格式和采样率”。不同厂商和接口版本分别校验，不能使用一个未经验证的公共选项集合。

无论供应商返回什么支持格式，进入样本库和导出训练包前统一归一化为：

- 16 kHz；
- 单声道；
- signed 16-bit little-endian PCM；
- WAV 容器。

随机语速、音高和供应商音量级由服务端根据任务 seed、文本、音色和样本序号确定性生成，并把每条样本的实际值写入数据库。供应商音量是接口规定的 `0–100` 相对控制量，不冒充声学 dB。相同配置和 seed 应可复现；不支持音高控制的接口不得静默发送无效值。裸 PCM 缺少采样率、通道数和位宽等自描述信息，页面不把 `.pcm` 列为可直接上传格式，应先封装或转换为 WAV。

## 费用边界

平台显示的金额统一称为“预估费用”。估算依赖管理员填写的供应商计费单位、单价、币种和当前请求的可计费数量。

预估费用不包含或不能准确反映：

- 免费额度和资源包抵扣；
- 阶梯价、地域价和合同折扣；
- 供应商延迟出账；
- 重试、超时和供应商对失败请求的最终计费判定；
- 后续价格调整。

页面和 API 都必须要求付费调用确认，并明确最终金额以云厂商账单为准。未配置价格时显示“未配置”，不能显示为零费用。

可能计费的 TTS 合成 POST 不做底层隐式自动重试：超时无法证明厂商未经处理原请求，自动重发可能导致重复计费。合成失败后只能由使用者在任务中心再次确认费用后显式重试；音色目录查询和音频下载仍可使用有上限的瞬时故障重试。

## 浏览器录音

网页录音包含麦克风授权、安全上下文检查、录音计时、输入电平、停止、试听、重录和上传。浏览器格式只作为传输格式，服务器仍执行音频归一化和时长校验。

点击“上传并校验”后，导入窗口保持打开，只清空本次已选择/已录制的音频；文本、标签、说话人、数据划分、性别和年龄继续保留。页面显示上一次校验结果，使用者可立即继续录音或选择下一批本地文件。主动关闭窗口才结束本轮连续导入。

局域网远程访问必须使用受信任 HTTPS；具体部署见 [`浏览器录音与HTTPS部署.md`](浏览器录音与HTTPS部署.md)。

## 兼容与迁移

- 旧任务没有父任务、可靠开始时间或费用信息，页面应显示为旧数据，不能猜测；
- 旧样本默认迁移为正样本，并按现有 provider、parent_id 推导来源和增强状态；
- 旧样本无法可靠反查原始总任务，`origin_job_id` 保持为空；
- 数据库迁移必须可以对现有库重复执行，不得删除样本或重写音频；
- 候选版本先在临时数据库和 Mock 供应商上验证，再备份生产 SQLite 并切换。

当前任务中心和样本库“按总任务”快捷筛选加载最近 500 个顶层任务。更早的样本仍会保留，也可以继续搜索和导出；任务量持续增长后，应把任务选择器升级为服务端分页搜索。
