# 语音数据集工坊：产品与部署说明

## 1. 定位

本项目用于制作中文关键词唤醒（KWS）数据集，覆盖：

```text
云 TTS / 真人录音
  -> 统一为 16 kHz、单声道、16-bit PCM WAV
  -> 试听与审核
  -> 背景噪声增强
  -> 按说话人分组划分数据集
  -> JSONL / folders / WeKWS ZIP
```

项目是独立社区工具，并非所接入云厂商的官方产品。它负责数据制作，不包含模型训练、板端推理或最终产品级 KWS 评估。

默认项目配置：

- 显示文本：`你好，小助手`
- 训练标签：`你好小助手`
- 内部 ID：`ni_hao_xiao_zhu_shou`

显示文本可以在网页左侧“当前 KWS 唤醒词”中修改。新配置只影响后续任务，不会静默改写已有样本。

## 2. 功能边界

### 2.1 音色与合成

- 提供少量内置音色元数据作为界面回退。
- 配置云厂商凭据后，可刷新当前接口和账号能够返回的音色。
- 支持按供应商、性别、年龄和关键词筛选。
- 支持多文本、多音色、每音色生成数量、语速、音量和随机种子。
- 音高是否可用取决于供应商接口；前端会对不支持的组合进行限制。
- 云端错误会脱敏后写入任务摘要，避免把完整凭据带入日志。

音色“可查询”不代表“可合成”。账号套餐、应用授权、地域和模型权限仍由云厂商控制。

### 2.2 样本管理

- 浏览器试听 WAV。
- 查看波形、频谱、时长、峰值、RMS 和静音比例。
- 修改文本、训练标签、性别、年龄、审核状态和标签。
- 导入真人录音并记录 `speaker_id` 和显式 split；说话人 ID 可从现有列表选择，也可直接输入新 ID。
- 真人音频上传校验后保留导入窗口及填写参数，可连续录音或选择下一批文件。
- 软删除样本并在短时间内撤销。

真人录音应按说话人划分，且不得把含个人身份或未授权语音的数据提交到公开仓库。

样本“类型”只分为“原音”和“增强样本”：所有未经过噪声增强的音频都属于原音；“真人录音”是来源，可通过厂商/来源筛选，不与类型混用。

### 2.3 噪声增强

- 上传 WAV、FLAC、MP3 等 `ffmpeg` 可解码音频。
- 配置噪声类别、权重和 SNR 范围。
- 使用固定随机种子选择噪声与起始偏移，便于复现。
- 生成增强样本时保留原始样本，通过 `parent_id` 关联。
- 一次增强操作创建一个总任务，每条源音频创建一个子任务；任务中心可展开查看明细。
- 增强输出固定标记为“增强样本、未审核”，不继承源音频审核状态。

当前增强是工程基线，不包含 RIR 卷积、响度标准化、VAD 对齐或设备频响模拟。正式数据集仍需要人工质检。

### 2.4 导出

| `format` | 音频目录 | 额外内容 |
|---|---|---|
| `generic` | `audio/{split}/*.wav` | Train/Dev/Test JSONL |
| `jsonl` | `audio/{split}/*.wav` | 与 `generic` 兼容 |
| `folders` | `folders/{split}/{keyword_id}/*.wav` | 同时保留 JSONL |
| `wekws` | `audio/{split}/*.wav` | 每个 split 额外生成 `text`、`wav.scp` |

复制音频时，ZIP 包含 `SHA256SUMS`。关闭复制音频时，清单引用训练环境可见的服务器路径，不适合搬到另一台机器直接使用。

同一个真人说话人，或同一个“TTS 供应商 + 音色 + 模型”组，不会跨 Train/Dev/Test。基础样本和其增强版本也不会跨组，避免明显的数据泄漏。

导出记录支持软删除：ZIP 移入 `trash/exports/`，默认列表隐藏记录，恢复接口可将文件移回导出目录。原始样本和任务记录不受影响。

## 3. 系统结构

```text
Browser
  -> FastAPI
      -> Provider adapters
      -> Background task pool
      -> Audio normalization / analysis / augmentation
      -> SQLite metadata
      -> Local WAV and ZIP files
```

关键文件：

```text
app.py                 FastAPI 路由、任务、样本和导出逻辑
providers.py           火山引擎、阿里云和本地 Mock 适配器
voice_catalog.py       内置回退音色目录
audio_utils.py         转码、分析与噪声混合
db.py                  SQLite schema 与轻量迁移
settings_store.py      云厂商凭据持久化
project_settings.py    可配置 KWS 唤醒词
static/                 无构建步骤的 HTML/CSS/JavaScript 前端
tests/                  不调用真实云服务的自动化测试
```

应用使用 SQLite 和进程内任务池，因此只运行一个 Uvicorn worker。`TTS_APP_WORKERS` 表示后台批处理线程数，不是 Web worker 数量。模板默认上限为 8，因此页面默认请求的并发数 3 不会被服务器静默压缩；多个任务同时运行时仍共同受这个全局上限约束。

## 4. Docker 部署

### 4.1 首次配置

```bash
cp .env.example .env
chmod 600 .env
mkdir -p var
id -u
id -g
openssl rand -hex 32
```

编辑 `.env`：

1. 将 UID/GID 设置为宿主机运行 Docker 的用户。
2. 将随机值设置为 `TTS_APP_API_TOKEN`。
3. 仅在需要局域网访问时，将 `TTS_APP_BIND_ADDRESS` 从 `127.0.0.1` 改为 `0.0.0.0`。

镜像内置非 root 用户，Compose 也会使用同一组 UID/GID 启动进程。`TTS_APP_UID` 和 `TTS_APP_GID` 必须是大于 0 的整数；首次启动前要确保 `TTS_APP_HOST_DATA_DIR` 可由该 UID/GID 写入。升级已有数据目录时不要直接改 UID/GID，除非已经完成备份并核对文件所有权。

不要把阿里云或火山引擎密钥写入 `.env`；它们在启动后的网页“供应商设置”中填写。

### 4.2 启动与检查

下面使用 Docker Compose v2。Compose v1.29 与 Docker Engine 29 在重建旧容器时可能报 `KeyError: 'ContainerConfig'`，优先安装 Compose v2。暂时只能使用 v1 时，应先确认数据是宿主机绑定目录并完成备份，再使用不带 `-v` 的 `docker-compose down` 后重新 `up`；不要直接假设 `--force-recreate` 可用。

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 tts-app
curl http://127.0.0.1:8080/healthz
```

默认回环访问地址：

```text
http://127.0.0.1:8080/
```

只有在已设置强随机 `TTS_APP_API_TOKEN`，并将监听地址改为 `0.0.0.0` 后，才使用局域网访问地址：

```text
http://<服务器局域网IP>:8080/
```

页面要求令牌时，点击右上角“访问令牌”。令牌只保存在当前浏览器会话的 `sessionStorage`。

### 4.3 停止和升级

停止但保留数据：

```bash
docker compose down
```

更新代码后：

```bash
git pull --ff-only
docker compose build tts-app
docker compose up -d --force-recreate tts-app
```

不要使用 `docker compose down -v` 删除尚未备份的数据卷。默认配置使用宿主机 `./var` 绑定目录，仍应在操作前确认实际挂载。

## 5. 数据与备份

默认宿主机目录：

```text
./var
├── tts_dataset.sqlite3
├── provider_settings.json
├── project_settings.json
├── samples/
├── noises/
├── exports/
├── trash/
└── tmp/
```

容器内映射为 `/data`。`provider_settings.json` 以 `0600` 权限保存，但内容仍是敏感数据。

旧版本留下的 SQLite、音频和导出文件可能仍为 `0644`。确认整个数据树都由 Compose 中配置的 UID/GID 独占后，可把目录收紧为 `0700`、普通文件收紧为 `0600`；若还有其他服务账号读取该目录，应先设计最小权限用户组，不能直接批量修改。

备份要求：

1. 避免在生成、增强或导出任务运行时备份。
2. 同时复制 SQLite、音频、噪声和导出目录。
3. 将备份视为敏感资产并加密保存。
4. 恢复后检查文件所有者、权限和应用健康接口。

不要提交：

- `.env`
- `var/` 或其他运行数据目录
- SQLite 数据库及 WAL/SHM 文件
- `provider_settings.json`
- 生成音频、真人录音、噪声和导出 ZIP
- 包含账号 ID、内网地址或个人身份信息的截图和日志

## 6. 云厂商配置

### 6.1 火山引擎

页面包含两组独立凭据：

| 用途 | 字段 |
|---|---|
| V1 短文本合成 | App ID、Access Token、Cluster |
| 公共音色目录 | Access Key ID、Access Key Secret |
| 账号复刻音色目录 | App ID、Access Key ID、Access Key Secret |

只填写 App ID/Access Token 可以合成已获授权音色，但不能完成公共目录签名查询；只填写 AK/SK 能够查询目录，也不代表语音应用具有合成权限。

参考文档：

- [火山引擎语音合成](https://www.volcengine.com/docs/6561/1354862)
- [火山引擎大模型语音合成 API](https://www.volcengine.com/docs/6561/2228192)
- [火山引擎音色管理 API](https://www.volcengine.com/docs/6561/2235883)

### 6.2 阿里云

页面支持 API Key、Workspace ID、地域和可选高级 Endpoint。当前非实时 `SpeechSynthesizer` 合成路径按北京地域适配。

公共音色由项目维护的兼容目录提供；账号自定义音色需要匹配的 Workspace、模型和地域权限。高级 Endpoint 默认只允许当前适配器使用的供应商官方主机，避免把凭据发送到第三方服务。自建 HTTPS 代理需要服务器管理员显式设置 `TTS_ALLOW_CUSTOM_PROVIDER_ENDPOINTS=1`，并自行承担代理可信性与密钥保管责任。

参考文档：

- [阿里云百炼语音合成](https://help.aliyun.com/zh/model-studio/text-to-speech)
- [阿里云百炼声音复刻](https://help.aliyun.com/zh/model-studio/qwen-tts-voice-cloning)

厂商 API、计费、参数和音色可能变化，使用前应重新核对官方文档。

### 6.3 费用与责任边界

本项目是自托管客户端，不销售、转售、代收或代付云服务。部署者在网页中填写自己的厂商凭据，请求直接计入对应云账号；由该账号产生的调用费、音色费、订阅费、超额用量和相关税费由账号持有人及实际使用者承担。

云端生成任务必须传入 `cost_acknowledged=true`。网页会要求使用者勾选费用确认并再次确认预计调用数量；任务重试也必须重新确认。这个机制只能降低误操作风险，不能替代厂商侧的预算、告警、配额和最小权限控制。

为避免网络超时后隐式重发可能计费的请求，云 TTS 合成 POST 不使用自动重试。失败项由使用者查看错误后，在任务中心再次确认费用并显式重试。

部署者应先在厂商控制台确认价格和授权，设置费用告警，并用一个音色、一条短文本和一个样本验证。详细边界和官方计费入口见 [使用、计费与责任说明](../DISCLAIMER.md)。

## 7. 主要 API

| 接口 | 用途 |
|---|---|
| `GET /healthz` | 无敏感信息的容器健康检查 |
| `GET /api/status` | 受应用令牌保护的状态与数据统计 |
| `GET/PUT /api/settings/project` | 查询或修改 KWS 唤醒词 |
| `GET /api/settings/providers` | 查询所有厂商的脱敏配置状态 |
| `PUT /api/settings/providers/{provider}` | 保存指定厂商配置 |
| `DELETE /api/settings/providers/{provider}` | 清空厂商配置 |
| `GET /api/voices` | 查询音色 |
| `POST /api/voices/refresh` | 刷新音色目录 |
| `POST /api/tasks/generate` | 创建批量合成任务；云端音色要求 `cost_acknowledged=true` |
| `GET /api/tasks` | 查询任务 |
| `GET /api/samples` | 分页查询样本 |
| `GET /api/samples/speakers` | 查询现有真人说话人 ID 及样本计数 |
| `POST /api/samples/upload` | 导入真人录音 |
| `POST /api/noises/upload` | 上传背景噪声 |
| `POST /api/augment` | 创建增强总任务及逐源音频子任务 |
| `POST /api/exports` | 创建导出任务 |
| `GET /api/exports/{id}/download` | 下载导出 ZIP |
| `DELETE /api/exports/{id}` | 软删除导出记录 |
| `POST /api/exports/{id}/restore` | 恢复导出记录 |

设置 `TTS_APP_API_TOKEN` 后，`/api/` 接口需要 `X-App-Token` 请求头。最小健康检查 `/healthz` 和静态页面保持可访问，以便容器探针和首次输入令牌。

## 8. 开发与验证

安装系统依赖后执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
pytest -q
python -m compileall -q .
node --check static/app.js
bash scripts/check_public_release.sh
docker build -t tts-2-datasets:check .
```

测试使用本地 Mock provider，不访问真实云 API，也不产生云服务费用。

## 9. 已知限制

- 没有多人账号、RBAC 或审计后台。
- 默认不提供 HTTPS；不要直接暴露到公网。
- 后台任务不会跨进程重启继续执行。
- 当前没有完整的回收站浏览和永久清理页面。
- 云端音色范围和合成能力依赖账号、地域和厂商接口。
- TTS 数据不能替代真人 Dev/Test、连续负音频误唤醒和目标设备远场评估。

## 10. 发布前检查

公开提交前至少运行：

```bash
bash scripts/check_public_release.sh
git status --short
```

检查 staged diff 中没有 `.env`、数据、日志、截图隐私、个人路径或真实账号信息。若密钥曾经被提交，应先轮换密钥，再使用合适的历史清理工具处理；普通删除提交不能从 Git 历史中移除秘密。
